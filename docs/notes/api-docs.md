# API docs UI

The node serves its OpenAPI reference at `/api-docs/index.html`, from `node/src/main/resources/api-docs/`. `CompositeHttpService` maps that directory with `getFromResourceDirectory("api-docs")`, and redirects `/`, `/swagger` and `/api-docs` to the index page. `openapi.yaml` is served by an explicit route that comes first, so the `{{version}}` and `{{networkId}}` placeholders get substituted; the copy under the static directory is never served raw.

The UI is Scalar (`@scalar/api-reference`), which replaced swagger-ui. It is a single vendored `standalone.js`, not an npm dependency, because the repo has no JS toolchain and the docs must render on a node with no outbound network.

## Never hand-edit standalone.js

`standalone.js` is generated by `vendor-scalar.sh` at the repo root and committed. Run `./vendor-scalar.sh --verify` to confirm the committed bundle matches a fresh build; it rebuilds into a temp file and diffs, leaving the tree untouched.

## The external-call cut

Upstream Scalar contacts its own hosted services at runtime. The agent chat fetches `api.scalar.com/vector/registry/*` on every page load, the default webfonts come from `fonts.scalar.com`, the request client falls back to the `proxy.scalar.com` CORS proxy, and OAuth token refresh falls back to `galaxy.scalar.com` for specs whose flow omits `tokenUrl`, which would send credentials there. None of that is acceptable for a node admin UI.

`vendor-scalar.sh` rewrites each of those origins to `https://scalar-services-disabled.invalid` (RFC 2606 reserved, so it cannot resolve). The cut is in the artifact rather than in runtime config because config is only a toggle: an upgrade can rename a flag or change its default and silently restore the calls. `index.html` also sets `agent: { disabled: true }` and `withDefaultFonts: false` so the dead code paths are not entered at all, but those are the convenience layer, not the guarantee.

The script asserts a minimum occurrence count per origin before substituting and fails if any survives. A zero count means upstream restructured the code and the cut missed something: re-audit the external calls before vendoring, do not just lower the count. Hosts left in place are navigation targets and example data, not background requests.

## Upgrading

Bump `VERSION` in `vendor-scalar.sh`, run it, copy the new checksum from the mismatch report into `UPSTREAM_SHA256`, rerun, then commit the regenerated bundle. Load `/api-docs/index.html` afterwards and confirm the browser devtools network tab shows only same-origin requests.

## Config that reproduces the old swagger-ui behaviour

`tagsSorter` and `operationsSorter` are `alpha`, matching the previous setup. `setPageTitle` replaces a custom swagger `TitlePlugin` that set the tab title from `info.title`. The two swagger CSS overrides were dropped: the `.try-out` rule is moot because Scalar always offers its request client, and the server-selector rule is unnecessary because the spec declares a single `/` server.
